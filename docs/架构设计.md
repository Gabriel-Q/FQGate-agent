# FQGate AI 插件架构

## 1. 边界

FQGate AI 接入由三个独立但有版本合同的部分组成：

```text
Codex / Claude Code
  ├─ 插件清单：发现 Skill 与 fqgate MCP
  ├─ Skill：选择工具并组织研究流程
  └─ MCP Apps host：渲染 ui:// 资源
                    │
                    ▼
FQGate 2.0 主程序
  ├─ MCP tools：只读标准数据能力
  ├─ MCP resources：OpenAPI、能力信息和 MCP Apps HTML
  ├─ MCP 会话：协议、取消、分页和 Apps 版本固定
  └─ MCP Apps updater：验签、安装、切换和回退
                    │
                    ▼
FQGate 数据源 Worker
```

Agent 仓库不实现行情服务，不保存 FQGate 二进制，也不拥有用户登录状态。主程序不维护 MCP Apps 的原生 HTML/CSS/TypeScript 源码，只内置经过校验的构建快照。

## 2. 为什么只有根级清单

仓库根就是插件根。`skills/` 和 `.mcp.json` 对 Codex、Claude Code 共用；`.codex-plugin/`、`.claude-plugin/` 与 `.agents/plugins/` 只补充宿主要求的发现元数据。

`plugin.json` / `mcp.json` 与点目录清单不是同一文件的随意副本：前者表达可移植 Agent Plugin 合同，后者是当前两个宿主实际读取的格式。除此以外不再保留 `AI-plugins/<host>`、`plugins/fqgate` 或打包时临时拼装的宿主目录。

## 3. Skill 设计

Skill 按用户目标划分，不按每一个 HTTP 接口划分：

| Skill | 必要工具范围 |
| --- | --- |
| 实时个股分析 | 证券搜索、对应市场行情、K 线；按需补资讯 |
| 条件选股 | 自然语言选股、沪深京行情、按需补 K 线 |
| 盘口与逐笔 | 分时、五档、普通逐笔，以及有权限时的 Level-2 |
| 事件研究 | 资讯分类、文章、重大事件、行情与 K 线时间轴 |

新增 Skill 必须满足：有独立用户目标；只引用 FQGate 2.0 实际发布的工具；区分事实与推断；明确权限和失败语义；增加路由评测。FQGate 2.0 没有交易工具，因此仓库不保留交易 Skill。

## 4. MCP Apps 所有权

源码和测试位于 `mcp-apps/`，配置入口为 `mcp-apps/mcp-apps/apps.json`。每个 App 声明版本化 `ui://fqgate/<bundleVersion>/<file>` URI 和实际 V2 工具路径。

稳定构建输出：

- 自包含 HTML，不依赖远程脚本或样式；
- `manifest.json`，记录大小与 SHA-256；
- `manifest.sig`，对版本清单做 Ed25519 签名；
- schema v2 的 `stable.json` / `stable.sig`，只使用相对资源路径，因此同一签名内容可由 GitHub 和 Gitee 镜像提供。

主程序在编译时嵌入一个稳定构建。运行时只接受内置公钥验证通过、最低 FQGate 版本兼容、文件哈希一致的远程版本。安装使用 staging 目录与原子切换；网络、签名或文件校验失败时继续使用当前版本。每个 MCP 会话固定一个 bundle 版本，防止会话中途界面 URI 改变。

## 5. AI 接入生命周期

FQGate 桌面端原生实现 Codex、Claude Code 接入，不依赖 Node.js 安装器：

1. `scan`：定位 CLI，读取版本、市场与已安装插件。
2. `plan`：给出将添加或移除的官方 CLI 资源；同名异源市场会阻止写入。
3. `apply`：重新计算计划并核对 `planId`，备份相关配置后执行固定参数的官方命令。
4. `rollback`：动作失败时按反向顺序撤销本次已完成动作。
5. `verify`：再次读取宿主状态，并调用本机 MCP `tools/list` 验收真实工具。
6. `uninstall`：只移除主程序所有权记录中的资源；用户原先已有的市场或插件不会被删除。

所有命令都使用封闭的客户端、动作和参数集合；界面不能传入任意命令。操作在后台线程执行并设有超时，不阻塞桌面事件循环。

## 6. 版本与发行

- `compatibility.json`：Agent 最低 FQGate 版本与 MCP 协议范围。
- 根级各插件清单：同一 Agent 版本。
- `mcp-apps/mcp-apps/apps.json`：独立的 Apps bundle 版本。
- 主程序 `assets/mcp-apps/embedded/manifest.json`：当前安装包内置版本。
- `FQGate-releases/releases/v2/mcp-apps/`：远程稳定通道和不可变版本目录。

Agent 源码仓库不保存正式 MCP Apps 历史版本，也不保存 FQGate 安装包。国内镜像属于 FQGate-releases 的发行职责，不在本仓库复制一套同步脚本。

## 7. 演进规则

能力演进顺序固定为：主程序先发布稳定工具合同，再更新 Skill 和 MCP Apps，最后发布签名 Apps 稳定通道。若接口、行为或目录调整会破坏已发布兼容性，必须先定义迁移合同，而不是增加永久兼容目录或双写路径。
