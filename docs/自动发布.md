# 自动发布

## Agent 插件

Codex 与 Claude Code 都从 Git 仓库的 Marketplace 入口安装插件，因此 Agent 版本通过普通代码评审进入 `main`，不再生成八套或九套 ZIP 包。版本变更必须同步：

- `package.json`
- `plugin.json`
- `.codex-plugin/plugin.json`
- `.claude-plugin/plugin.json`
- `.claude-plugin/marketplace.json`
- `compatibility.json`
- `RELEASE_NOTES.md`

合并前运行 `npm test`。本仓库的 Gitee 源码镜像可独立配置，但不得承担 FQGate 主程序或 MCP Apps 稳定通道的发布职责。

## MCP Apps

MCP Apps 独立版本化。发布前先在 PR 中更新：

```bash
node mcp-apps/scripts/prepare-mcp-apps-version.mjs \
  --version <新版本> \
  --minimum-fqgate-version <最低主程序版本>
npm test
npm run embed:mcp-apps -- --fqgate-root ../fqgate
```

最后一条命令更新主程序仓库的内置快照，应与相关 FQGate 变更一起评审。它不包含私钥，也不会生成远程稳定通道。

Agent `main` 合并后，在 GitHub Actions 手动运行“发布 MCP Apps”，输入与 `apps.json` 一致的版本。工作流会：

1. 重新运行全部门禁；
2. 使用受保护环境中的 Ed25519 私钥构建和签名；
3. 使用 FQGate 主程序内置公钥验收；
4. 向 `fqgate/FQGate-releases` 的 `releases/v2/mcp-apps/` 写入不可变版本目录；
5. 最后切换签名的 `stable.json` 与 `stable.sig`。

发布需要 `FQGATE_MCP_APPS_ED25519_PRIVATE_KEY` 和能写入发行仓库的 `FQGATE_RELEASES_TOKEN`。私钥不得保存到仓库、构建产物或日志。

`FQGate-releases` 自己负责把相同提交镜像到 Gitee。由于稳定指针只包含相对路径，同一份签名可在两个源上验证，主程序会按 GitHub、Gitee 顺序尝试。

## 回滚

已经发布的版本目录不可覆盖。需要回滚时，使用同一私钥重新签名一个指向既有兼容版本的稳定指针，并通过发行仓库的受控流程切换。主程序不会删除内置版本或当前进程中仍被会话引用的版本。
